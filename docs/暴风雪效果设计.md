# 暴风雪效果设计 v1

状态：2026-11-05 用户确认，代码已接入，验证记录见文末。灾种 ID `naturaldisaster:snow_storm`。

## 边界

暴风雪只消费现有生命周期的 `effectActive` 和当前区块覆盖结果。预警无效果；增长、衰退生效；结束停止。严禁灾种修改事件时长、阶段、半径或中心轨迹。默认仍为600秒、60秒预警、最大8区块。

## 灾种解析

以事件开始运动帧所在区块为基础，固定取区块中心的生成地表群系，经 `BiomeDisasterTypes` 映射；中心移动后不重新选种。取样 x/z 为 `chunk*16+8`，y 为生成器 `WORLD_SURFACE_WG` 高度减1并夹取到建造高度。用生成器 biome source 与 noise sampler 获取，不读取/加载开始区块，不依赖加载次序或玩家地形改造。灾种和开始区块缓存仅是可重建派生数据，按事件 `startTick` 校验并随活动候选消失而丢弃，不持久化。

## 玩家

在暴风雪覆盖区块内显示降雪、雾色 RGB(210,220,230)、能见度上限3区块（48格，不提高原本更低的能见度）。玩家内部使用不序列化的attachment保存“是否渲染天灾”的目标标记，服务端覆盖变化时同步，客户端由此用40tick（2秒）淡入/淡出；边缘反复切换从当前强度反向过渡，不归零重播。按partial tick做帧内插值，不影响服务端判定。

雪花与原天气分两层交叉淡化，雨天也不会在淡出终点突然由雪变雨。雾色与原有颜色混合；能见度通过连续雾距离过渡到最多3区块（48格），暴风雪不再修改客户端真实渲染距离选项，避免整数视距跳变、区块重建及加载范围抖动；通用debug视距接口保持原行为。独立雪层不再写客户端全局雨/雷强度，天空保持原版天气。预警仍不触发标记，退出只留下视觉淡出，缓慢和地表结算不延长。

附件不写存档、不复制重生进度。登出和换世界立即清除旧世界状态；新维度/重生按当前覆盖重新同步。多中心覆盖先合并后再更新标记，不由单中心退出提前触发淡出。网络协议升至6。

生存/冒险玩家露天且满足覆盖/实体模拟门槛时，每tick调用 `SnowStormEffects.freezePlayer(ServerPlayer)`，内部按Cold Sweat是否安装分支：存在时施加WORLD环境降温；缺失时施加缓慢I/60tick并慢速积累原版冻结值（详见下方2026-11-06调整）。药水与温度修饰器按20tick节流，露天复用 `DisasterEffects.isPlayerExposed(UUID)`。创造、旁观和死亡玩家不施加玩法效果。进入屋顶下或离开范围后清除本模组暴露状态及温度修饰器，原版冻结值自然消退；缓慢最多3秒自然消失，不删除其他来源药水。不直接写Cold Sweat体温，也不自行重做原版冻伤逻辑。

统一分发器汇总后处理恢复，多个暴风雪不叠级、不互相提前清除。离开范围/事件结束恢复天气、雾色与进入前视距；换维度和重生重新判断；登出丢弃投递记录、客户端恢复；重新登录重新判断。投递记录不是事件状态，不进入存档。

## 地表

复用地表天灾刻，每受影响区块每tick默认2点。叠加中心仍只采样一次。只在已加载且具备 block-ticking 资格的区块结算；操作前要求3×3邻区均已加载。`LoadedEffectScope` 和 `LevelEffectAccessMixin` 在同步结算期间对未加载区块的方块/流体/方块实体读取返回空边界值、拒绝方块写入，避免原版红石等邻居回调经这些API加载新区块，同时保留正常更新层数；不全局改变原版tick，也不拦截任意模组直接区块API或延迟回调。跳过不追溯。单点按优先级执行，最多一种操作：

1. 方块命中破坏列表且硬度非负：调用原版破坏/掉落流程，遵循 `doTileDrops`，不模拟工具、精准采集或时运；同次采样不继续向下找方块或放冰雪。
2. 未执行破坏且为露天水源方块：转为普通冰。不冻结流动水、含水方块或水下方块。
3. 其他情况：已有雪层增加一层（最多3层，仍需合法支撑）；否则仅在上方空气且雪层可存活时放一层雪。不替换植物、流体或其他占用方块。

积雪与结冰不检查群系温度；后续融化遵循原版。地表变化不回滚。默认破坏清单含玻璃方块和农作物，玻璃板不在默认内。配置空列表只关闭破坏，不关闭冰雪。`surfaceDisasterTickSpeed=0`关闭全部地表效果，不影响玩家效果。全高度随机采样暂无暴风雪效果。

## 配置

```toml
[snowStorm]
breakableBlocks = ["#c:glass_blocks", "#minecraft:crops"]
```

支持精确 `namespace:block_id` 与 `#namespace:block_tag`，条目取并集。语法和注册表/标签错误逐条警告跳过，不清空其他有效条目；启动时绑定。标签匹配依赖数据包标签。配置只影响后续结算，不改变中心场指纹、中心位置或事件时间，不补算历史。

## 验证

### 2026-11-06 冻结分支调整

`freezePlayer` 使用 `NaturalDisaster.COLD_SWEAT_LOADED` 分支：安装Cold Sweat时只通过独立兼容类施加WORLD环境降温（当前默认相对降低20°C，可配置），不额外施加本模组缓慢或原版冻结；未安装时保留缓慢I/60tick并积累原版冻结值。覆盖、露天、非创造/旁观、存活及实体模拟门槛保持由效果投递层判断；每tick刷新玩家瞬时暴露状态，药水与温度修饰器按20tick节流。

无前置时，暴风雪将原版非细雪的解冻步骤替换为每4tick增加1点（细雪每tick增加1点），上限沿用原版140点，约28秒达到完全冻结；真实细雪仍使用原版速度。复用原版冻结显示、减速和冻伤，尊重`canFreeze`（包括皮革装备免疫）及火焰解冻。离开范围、遮蔽或不再满足门槛后停止保持冻结值，恢复原版每tick减少2点。短期玩家暴露附件不序列化、不复制重生、按世界对象和最近刷新tick失效。

Cold Sweat修饰器注册为`naturaldisaster:snow_storm`，在方块温度前插入以保留后续取暖/保温计算，同一玩家至多一个，覆盖时续期、退出立即移除，40tick到期兜底；计算时再检查瞬时暴露状态，防止重登或换世界后残留降温。使用官方MC1.21.1 NeoForge 2.4.5发行版作为编译依赖，默认不由Gradle加入运行类路径（`run/mods`另行存在的JAR仍会被加载）；`-PwithColdSweat=true`将依赖加入开发运行。两条分支均只消费既有天灾覆盖，不修改生命周期。

### 2026-11-06 可调强度与护甲保护

`snowStorm`新增效果配置，不改变场指纹或生命周期：

```toml
[snowStorm]
coolingCelsius = 20.0
freezingIntervalTicks = 4
```

`coolingCelsius`为正数降温幅度，范围0–200°C，0不降温；Cold Sweat的已有修饰器缓存函数也读取当前配置。`freezingIntervalTicks`为无Cold Sweat时每增加1点冻结值的tick间隔，范围0–1200，数值越小越快，0关闭暴风雪积累并恢复原版解冻；默认4仍为细雪速度的四分之一。

暴风雪原版冻伤只在头盔、胸甲、护腿、靴子至少一个槽为空时允许发生；四槽全满时拦截冻伤，冻结值和缓慢仍保留。原版`canFreeze`免疫继续有效，不改变真实细雪的冻伤及Cold Sweat自身的温度后果。

验证：本轮打包、6项相关JUnit、无Cold Sweat/有Cold Sweat两套独立目录各7项GameTest全部通过。新增检查覆盖冻结间隔4/2/0的实际积累与解冻、满四槽阻止冻伤、四个槽分别缺失时允许原版冻伤、穿满铁甲仍受真实细雪冻伤，以及20°C降温、缓存函数响应30°C和0°C配置。未修改中心场或生命周期生产代码；未进行本轮客户端目视验收。

### 游戏内启用

冰雪群系现在默认映射为暴风雪，无需手动填写配置。默认标签 `naturaldisaster:snow_storm_biomes` 合并 `c:is_snowy`、`c:is_icy` 和 `c:is_aquatic_icy`，覆盖以下11个原版群系，并包含模组加入这些标签的群系：

- `minecraft:snowy_plains`、`minecraft:ice_spikes`、`minecraft:snowy_taiga`、`minecraft:snowy_beach`
- `minecraft:grove`、`minecraft:snowy_slopes`、`minecraft:jagged_peaks`、`minecraft:frozen_peaks`
- `minecraft:frozen_river`、`minecraft:frozen_ocean`、`minecraft:deep_frozen_ocean`

普通针叶林、裸岩山峰等非冰雪标签群系仍为 `dummy`。配置 `biomeToType` 仍默认空列表，但空列表表示使用上述内置默认，不再表示全部dummy；已有空配置同样生效。优先级为精确群系配置 > 标签配置 > 内置冰雪默认 > dummy。需要禁用某群系时，可显式覆盖为dummy并重启，例如：

```toml
[disasterTypes]
biomeToType = ["minecraft:snowy_plains=naturaldisaster:dummy"]
```

无需修改中心配置，也不需要新增生命周期计时器。协议版本已升至6，客户端和服务端需使用同一版模组。
