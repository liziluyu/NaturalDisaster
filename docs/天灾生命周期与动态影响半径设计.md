# 天灾生命周期与动态影响半径设计

> 版本：v3 · 2026-10-29（运动采样帧 200 → 20 tick）  
> 状态：实现已与本次代码同步（`Config` 默认值、`EventState`、查询与快照）；本轮未运行游戏、单元测试或 GameTest，因此不声称任何运行验证通过  
> 目标配置：天灾总时长 `D = 600 s = 12000 tick`，最大影响半径 `R = 8` 区块  
> 本文是《天灾中心系统-设计与决策汇总.md》的专项补充，规定天灾从出现到结束的生命周期、动态半径、地图状态与查询约束。本文与主文档同步描述当前代码行为；两者冲突时，阶段、时长、半径与查询语义以本文为准，通用场算法与性能口径以主文档为准。

---

## 1. 目标与不变约束

本轮调整解决两个问题：

1. 天灾不再是整个生命周期都保持最大半径的圆，而是经历**预警、增长、衰退**三个阶段。
2. 动态半径不能破坏“玩家／加载区拉取附近中心”的完整性：中心即使不在加载范围内，只要其影响圈覆盖已加载区块，就必须被发现。

以下基础决策不变：

- 天灾中心与事件仍由 `(world seed, gameTime, dimension, center id, config)` 纯函数决定。
- 不保存生命周期状态机，不记录“已经增长到多少”，读档后按当前 tick 直接重算。
- 中心位置按 `20 tick = 1 s` 的运动帧量化；动态半径使用同一个**包含 tick 的全局**运动帧 `motionTick = floor(tick / 20) * 20`。采样加密不改变样条路径、段长或速度。
- 阶段（是否存在、`WARNING/GROWING/DECAYING`、`effectActive`）使用**真实** `elapsed = tick - startTick`；只有半径使用 `e = motionTick - startTick`，不做帧内插值。
- 语义严格按用户给定公式：奇数 `R` 造成的上下半不对称、衰退末端可能到 0 半径，均**不修正**；不擅自改成成对取整或最小半径。
- 只对已加载区块施加效果，不强加载中心所在区块，不追溯未加载区块。
- 查询候选必须按**配置的最大半径**扩张，不能按某一帧正在变化的当前半径扩张。

## 2. 参数与时间轴

### 2.1 目标参数

| 符号 | 含义 | 目标值 | 说明 |
|---|---|---:|---|
| `D` | 一次天灾从出现到结束的总时长 | `600 s = 12000 tick` | **包含**60 秒预警，不是预警之后再增加600秒 |
| `R` | 配置的最大影响半径 | `8` 区块 | 即128格；也是所有查询使用的半径上界 |
| `W` | 固定预警时长 | `60 s = 1200 tick` | 固定值，不随 `D` 缩放 |
| `G` | 增长阶段时长 | `D / 2 = 300 s = 6000 tick` | 从最大半径的50%增长到100% |
| `F` | 衰退阶段时长 | `D - W - G = 240 s = 4800 tick` | 从100%衰退到50% |
| `M` | 位置／半径运动帧 | `20 tick = 1 s` | 每个运动帧重算一次位置与半径 |

`W = 60 s = 1200 tick` 是生命周期设计常量；实现时应把 `W`、`G = D/2`、`F = D - W - G`、取整规则和算法版本一起纳入配置指纹。`G = D / 2` 与 `F = D - W - G` 决定合法域：**必须满足 `D > 2W`**，否则 `F = D/2 - W <= 0`，衰退阶段不存在。Java 配置 `disasterDurationSeconds` 的下限必须把 `D > 2W` 纳入（当前实现下限为 121 秒），`FieldParams` 构造时再按 tick 精确校验 `disasterDurationTicks > 2 * WARNING_TICKS`；当前默认 `D = 600 s`、`W = 60 s`，故 `F = 240 s > 0`。校验必须在构造参数时完成，而不是在事件计算中静默截断。

### 2.2 阶段划分

设天灾算法决定事件开始的时刻为 `t0`，实际经过时间为：

```text
elapsed = tick - t0
0 <= elapsed < D  时，本次天灾存在
```

| 阶段 | 经过时间（tick） | 半径目标 | 地图表现 | 实际效果 |
|---|---|---|---|---|
| 预警 `WARNING` | `[0, 1200)` | `ceil(R/2) = 4` 区块 | **黄色** | **无任何天灾效果** |
| 增长 `GROWING` | `[1200, 7200)` | 从50%线性增长到100% | 活动天灾颜色（当前为红色） | 生效 |
| 衰退 `DECAYING` | `[7200, 12000)` | 从100%线性下降到50% | 活动天灾颜色（当前为红色） | 生效 |
| 结束 | `elapsed >= 12000` | 不再存在 | 移除 | 停止 |

`elapsed = 12000 tick` 时事件已经结束；衰退公式的终点50%用于保证结束前的最后一段达到最小半径，而不是在结束后继续保留一个4区块事件。阶段边界按真实 `elapsed` 精确到 tick，不按运动帧；因此阶段切换可能发生在 `motionTick` 之间，半径要到下一个运动帧才跳变。帧量化还允许 `e = motionTick - t0 < 0`（`t0` 落在两帧之间时），此时公式按 `clamp` 取预警半径，属正常行为。

## 3. 动态半径公式

### 3.1 半径统一使用运动帧时间

对每个查询 tick：

```text
step       = floor(tick / 20)
motionTick = step * 20
e          = motionTick - t0
```

半径只使用 `e` 重算，在运动帧内保持不变。这样同一帧的圆心和半径来自同一个 `motionTick`，不会出现“圆心已经移动、半径却来自另一帧”的组合。`motionTick` 是**全局**帧（`floor(tick/20)*20`），不是相对 `t0` 的帧，因此 `e` 不一定是 20 的倍数，也**可能为负**：当 `t0` 落在两帧之间时，`motionTick < t0`，`e < 0`，公式经 `clamp` 后取预警半径。

生命周期是否存在、当前处于哪个阶段，以及效果是否开启，仍由真实 `tick - t0` 判定；只有半径被量化。因此阶段切换后，半径最多等到下一个运动帧才跳变，**最多滞后 19 tick**（不是 20），不做帧内插值。验收必须按这一量化行为判定，不能要求半径在阶段边界当 tick 立刻变化。

### 3.2 通用公式

以下长度单位为区块：

```text
B = R / 2.0
```

- **预警阶段**：`radius = ceil(B)`。
- **增长阶段**：

```text
u = clamp((e - W) / G, 0, 1)
radius = ceil(B + (R - B) * u)
```

- **衰退阶段**：

```text
v = clamp((e - W - G) / F, 0, 1)
radius = floor(R - (R - B) * v)
```

边界约定：

- 增长起点 `u = 0`，从50%开始。
- 增长终点／衰退起点为100%，两个阶段在边界上半径一致。
- 衰退终点 `v = 1`，回到50%。
- 向上取整可通过 `-floor(-x)` 实现，不引入跨平台未批准的浮点函数。

取整与不对称是用户明确指定的语义，实现**不得修正**：

- 预警与增长用 `ceil`，衰退用 `floor`，因此 `R` 为奇数时上下半程并不对称（例如 `R = 5` 时预警为 `ceil(2.5) = 3` 区块，增长从3到5，衰退末端为 `floor(2.5) = 2`，回到2而不是3）。
- 该不对称是有意为之，不接受“上下半对称”之类的数学美化。
- 当 `R = 1` 时，衰退公式末端可得到 `floor(1 - 0.5 * 1) = 0` 区块；0 半径意味着当帧不覆盖任何区块，是合法结果，不施加最小半径下限。
- 不要在实现中引入额外的最小半径、四舍五入或成对取整；所有整数结果都直接由上述公式与 `clamp` 得出。

### 3.3 600 秒／8 区块示例的代入结果

以下所有边界与代入变量均为 tick。`e = motionTick - startTick` 在单个运动帧内恒定，相邻帧相差 20；其具体值取决于 `startTick` 的帧内相位，不保证是 20 的整数倍。下表按 `e` 取值说明公式，边界与阶段仍由真实 `elapsed` 判定，因此增长／衰退刚切换时半径可能短暂停留在旧值。

预警半径分支，`e < 1200`：

```text
radius = 4 区块
```

增长分支，`1200 <= e < 7200`：

```text
radius = ceil(4 + 4 * (e - 1200) / 6000)
```

衰退分支，`7200 <= e < 12000`：

```text
radius = floor(8 - 4 * (e - 7200) / 4800)
```

示例取值：

| `e`（tick） | 半径分支 | 半径（区块） |
|---:|---|---:|
| 0 或负值 | WARNING | 4 |
| 1 100 | WARNING | 4 |
| 1 200 | GROWING | 4 |
| 1 950 | GROWING | 5 |
| 3 450 | GROWING | 6 |
| 4 950 | GROWING | 7 |
| 7 199 | GROWING | 8 |
| 7 200 | DECAYING | 8 |
| 8 400 | DECAYING | 7 |
| 9 600 | DECAYING | 6 |
| 10 800 | DECAYING | 5 |
| 11 999 | DECAYING | 4 |

这里的“向上取整”和“向下取整”是有意不对称的：

- 增长阶段在越过整数阈值后立即进入较大的整数半径。
- 衰退阶段在越过整数阈值后立即进入较小的整数半径。
- 实际跳变时刻还要对齐到20 tick运动帧，不能逐 tick 平滑变化。上表是公式在 `e` 上的取值；真实查询中阶段由 `elapsed` 决定，半径由 `e` 决定，两者可能短暂不同步。

## 4. 事件生命逻辑调整

### 4.1 保留纯函数时隙，不引入状态机

现有时隙规则继续负责“何时产生一次天灾”：

- 时隙长度 = `D = disasterDurationSeconds * 20`，默认 `600 s → 12000 tick`。
- 每中心保留独立相位；本时隙中签且上一时隙未中签时，产生一次事件。
- 每次事件仍恰好持续 `D`，之后至少空闲一个时隙。
- 事件触发概率、中心位置算法与灾种选择不因动态半径而改变。

生命周期只是从 `tick、startTick、D、R` 派生的额外结果，不得保存 `phase`、上一帧半径或增长进度。

### 4.2 “事件存在”与“效果生效”分离

事件查询结果由不可变 `record` 表达，字段固定为：

```java
record EventState(
    boolean active,      // 是否处于 [startTick, startTick + D) 生命周期内
    long startTick,      // t0
    long elapsed,        // tick - startTick，真实 tick，非运动帧
    long remaining,      // startTick + D - tick
    Phase phase,         // NONE / WARNING / GROWING / DECAYING
    boolean effectActive,// WARNING 为 false；GROWING / DECAYING 为 true
    int radiusChunks     // 按运动帧 e 计算的当前整数半径
) {}

enum Phase { NONE, WARNING, GROWING, DECAYING }
```

- 不在生命周期内时返回 `INACTIVE`：`active = false`、`phase = NONE`、`effectActive = false`、`radiusChunks = 0`；`startTick/elapsed/remaining` 不得被调用方当作有意义值。
- 配置的最大半径 `R`（`disasterRadiusChunks`）**不放进** `EventState`：它属于配置，查询与地图外扩直接从配置读取，避免把两个来源的半径混用。
- 预警事件也是已发生的天灾，必须能进入地图快照；只是 `effectActive = false`。不能因为预警无伤害就把它当作不存在，否则地图无法提前60秒显示黄色范围。

按现有 `p = 0.35` 的互斥时隙规则，事件生命周期的时间占比仍约为 `p(1-p) = 22.75%`。其中只有 `D - W = 10800 tick` 具有实际效果，因此效果时间占比约为 `22.75% * 10800/12000 = 20.5%`；该数值是理论长期占比，不保证局部同时发生数量。

## 5. 查询与加载范围：禁止动态半径漏检

### 5.1 查询始终使用最大半径8区块

无论当前事件处于预警、增长还是衰退，玩家侧拉取与加载区块查询都必须按 `R = 8` 区块扩张：

1. 用最大半径查出所有可能影响目标区域的中心。
2. 对每个中心求事件生命周期与当前运动帧半径。
3. 再用**当前半径**筛选实际覆盖的区块。

禁止先使用当前半径（预警时为4区块）缩小中心查询范围。当前半径只负责最终覆盖判定，不负责决定候选中心是否值得检查。对未激活中心，覆盖判定沿用配置最大半径，以保持现有命令的返回语义；动态半径只作用于 `active` 事件。

巢域候选仍按 `maxTotalRadius + R` 扩张；中心所在区块是否加载与查询无关。因此“中心在加载区外，但当前动态影响圈覆盖加载区”仍会被发现。

### 5.2 两条查询路径的共同约束

- **玩家侧快照路径**：区域半径与中心查询外扩均使用配置的最大半径 `R`，不能用某一事件的当前半径替代。
- **已加载区块覆盖路径**：候选锚点按总巢域位移加最大半径扩张，命中中心后再以当前事件半径执行 `coversChunk` 等效判定。

只要所有事件的半径都不超过配置最大值 `R`，动态生命周期就不会引入“远处大天灾没有进入查询”的新漏检窗口。

## 6. 地图呈现与多事件重叠

### 6.1 黄色预警与红色活动状态

地图快照必须区分两类区块：

- `WARNING`：黄色（`#ffff00`），只展示范围，不施加效果。
- `GROWING / DECAYING`：活动天灾红色（`#ff0000`），并允许施加效果。

实现上，`DisasterSnapshotPayload` 携带两个**互不重叠**的区块 long 列表：`warningChunks` 只含阶段为 `WARNING` 的区块，`effectChunks` 只含 `effectActive = true`（增长/衰退）的区块。服务端先取并集再按“红色优先”把活动区块从预警列表中移除，因此同一区块不会同时出现在两个列表。载荷版本为 2，每个列表分别受 `MAX_CHUNKS = 20000` 编解码限制，服务端总量亦不超过 20000。客户端按维度保存不可变的有序 `long[]` 对；Xaero 渲染器黄色 `#ffff00`、红色 `#ff0000`、透明度 0.35，并先画黄色、后画红色（红色覆盖黄色）。只发送当前已加载且被事件覆盖的区块，范围裁剪与发送周期沿用现有限制；不强加载、不结算未加载区块。渲染只按快照状态上色，不在客户端重算阶段或半径。

### 6.2 重叠规则

同一区块被多个事件覆盖时：

1. 只要任一覆盖事件 `effectActive = true`，该区块按活动天灾处理，地图显示红色。
2. 否则，只要任一覆盖事件处于预警，该区块显示黄色且维持无效果。
3. 红色优先于黄色；不能因后加入一个预警事件把已有活动区块降级成黄色。
4. 天灾是否生效按区块聚合判定，不因覆盖中心数量重复叠加同一次基础效果；具体灾种如需额外叠加强度，必须另行定义。

中心或半径进入下一运动帧后，地图在下一次快照中替换旧范围；不保留历史圆形，也不把曾经覆盖的区块永久染色。

## 7. 效果结算边界

- 预警阶段仅展示，不执行伤害、天气、刷怪、方块改变或其他天灾效果。
- 增长与衰退阶段都执行效果，区别只有当前半径；阶段名称本身不代表效果强度。
- 效果只作用于已加载且位于当前半径内的区块。
- 半径缩小时，新范围外的区块立即停止该事件提供的效果；不追溯、不补算，也不要求撤销已经合法产生的永久结果。
- 玩家侧拉取负责发现加载区外中心，不能改回“只有中心区块已加载才检查事件”。

## 8. 实现状态与验收标准

截至本文更新，以下内容已与代码同步（同一次变更）：

1. 纯事件结果 `EventState` 扩展为 `active / startTick / elapsed / remaining / phase / effectActive / radiusChunks`，`Phase` 为 `NONE/WARNING/GROWING/DECAYING`；无事件时 `INACTIVE`。
2. `Config` 默认值改为 `disasterDurationSeconds = 600`（12000 tick）、`disasterRadiusChunks = 8`；配置下限与 `FieldParams` 构造校验共同保证 `D > 2W`（`W = 1200 tick`）。
3. 阶段按真实 `tick` 判定，半径按全局 20 tick 运动帧重算；增长 `ceil`、衰退 `floor`。
4. 所有查询保持按配置最大半径 `R` 扩张，再按当前 `radiusChunks` 过滤。
5. 快照使用互不重叠的 `warningChunks` / `effectChunks`（载荷 v2），红色优先。
6. 效果接入严格以 `effectActive` 为开关；预警不结算。

本文只声明代码结构与语义已同步，**本轮未运行游戏、单元测试或 GameTest**，因此不声称上述行为已通过运行验证；编译之外无验收数据。

至少验收以下情况：

- 同一事件在任意读档、重复查询下得到相同 `startTick`、阶段和半径。
- 预警恰好 `1200 tick`，期间半径4区块、地图黄色且无任何效果。
- 增长使用 `6000 tick` 并向上取整，衰退使用 `4800 tick` 并向下取整。
- 半径在同一20 tick运动帧内恒定，圆心与半径使用同一 `motionTick`；相邻帧可跳变。
- 增长与衰退在 `elapsed = 7200` 边界半径均为8区块；事件在 `elapsed = 12000` 整结束。
- 运动帧量化：`startTick` 不落在20 tick边界时 `e` 可为负，预警半径仍为4区块；阶段切换后半径最多滞后19 tick，不要求帧内插值。
- 奇数 `R`（如5）不修正上下半不对称；`R = 1` 时衰退末端可为0区块且不施加最小半径。
- 负 tick、事件边界、运动帧边界和跨区块边界结果确定。
- 中心在加载区外、当前圆覆盖加载区内时仍能被发现。
- 当前半径缩小到4区块时，查询仍按8区块最大值扩张，不漏候选中心。
- 黄色与红色重叠时显示红色，预警不会关闭另一活动事件的效果；同一区块不同时出现在两个快照列表。
- 未加载区块不结算、不强加载、不追溯。
